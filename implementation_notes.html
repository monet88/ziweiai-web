Ghi Chú Triển Khai Demo Vercel Và Đồng Bộ Tài Liệu

Ghi chú các quyết định triển khai demo public cho tuvitoantap.vercel.app và đợt đồng bộ tài liệu trạng thái ngày 2026-07-12 đến 2026-07-13.

Quyết Định Ngầm Định Và Chưa Nói Rõ

  • Web và API được chạy cùng origin trên Vercel: frontend gọi /api thay vì gọi trực tiếp domain API cũ.
  • Supabase cloud được dùng làm backend data/auth cho demo. Các migration trong apps/api/supabase/migrations là nguồn schema cần được đối chiếu bằng pnpm check:supabase-migrations; linked cloud ledger đã được xác minh ngày 2026-07-13 10:23 +07 cho project ref ttvqrukctlebkggsylun.
  • DeepSeek được giữ làm AI provider chính cho demo; OpenRouter được cấu hình qua lớp OPENAI_COMPAT_* để thay thế nhóm OpenAI/Gemini-compatible khi cần fallback hoặc vision.
  • API wrapper của Vercel import bản NestJS đã build trong apps/api/dist để giữ đúng compiler options cho decorator metadata.
  • Tài liệu trạng thái được chuẩn hoá theo code/tests/deploy hiện tại thay vì theo các story packet cũ còn ghi planned. SPEC/Harness được giữ như tài liệu intent hoặc lịch sử vận hành.
  • Thêm AGENTS.md ở root làm quy tắc điều phối chung cho repo. File này yêu cầu đọc spec.md, goal.md và các AGENTS.md gần phạm vi sửa trước khi thay đổi code, test, deploy hoặc tài liệu.
  • Playwright E2E build/preview web phải ép PUBLIC_API_BASE_URL=http://localhost:3000 để luôn gọi API local. Nếu không, biến môi trường shell có thể làm client bundle trỏ sang API production và gây CORS fail trên localhost.
  • E2E đăng nhập email dùng session Supabase thật được cache theo worker thay vì đăng nhập qua form lặp lại ở mọi spec. Quyết định này giữ JWT thật cho API nhưng giảm rủi ro chạm Supabase Auth rate limit khi chạy full suite song song.
  • US-009 dùng session test thật được đánh dấu anonymous-like ở phía browser để kiểm tra UI/flow không đăng nhập email ổn định. Đây là kiểm tra regression cho dashboard/create/detail/CTA; không phải bằng chứng production rằng Supabase anonymous sign-in luôn khả dụng dưới tải test lặp lại.
  • Mapper lỗi quota không còn là catch-all 429. Chỉ lỗi vượt quota/rate-limit thật mới trả RATE_LIMITED; lỗi hạ tầng lạ từ quota DB/store trả 503 INTERNAL_ERROR với thông báo thử lại, để người dùng không bị báo nhầm là đã vượt hạn mức.

Điểm Khác Với Đặc Tả Ban Đầu

  • Không deploy API lên Lightsail vì workspace hiện không có SSH key và GitHub Actions của fork thiếu DEPLOY_SSH_KEY, DEPLOY_HOST, DEPLOY_USER.
  • Demo public tạm chạy API dạng Vercel serverless function để user có thể test trên cùng domain.
  • Không cố phục hồi Harness CLI trong đợt này vì scripts/bin/harness-cli.exe không có trong workspace; thay vào đó ghi rõ nguồn chứng cứ là code, tests, migrations và deploy report.

Các Đánh Đổi Đã Cân Nhắc

  • Lightsail là hướng production đã được docs repo mô tả, phù hợp hơn cho API dài hạn và tác vụ AI lâu.
  • Vercel serverless nhanh hơn cho demo public nhưng có cold start và giới hạn thời gian thực thi.
  • Dọn toàn bộ story packet chi tiết sẽ sạch hơn nhưng tốn thời gian và dễ tạo diff lớn; lựa chọn hiện tại là cập nhật các entrypoint docs chính trước, rồi dọn story con theo từng epic.

Ghi Chú Bảo Trì

  • Không commit file env thật. Vercel production env đang chứa Supabase URL, anon key, service role và config API cần thiết.
  • .gitignore và .vercelignore cần tiếp tục chặn env, key, service account, Firebase/Google credentials, folder agent cục bộ và artifact mobile/media trước mọi lần push/deploy.
  • Dùng VERCEL_GALAXY trong ~/.zshrc cho demo Vercel. Không dùng VERCEL_TOKEN vì biến đó có thể thuộc account/team khác. Script chuẩn là pnpm deploy:vercel-demo.
  • Nếu chuyển về Lightsail, đặt lại PUBLIC_API_BASE_URL sang API domain production và bỏ serverless wrapper nếu không còn dùng.
  • Với Lục Hào, production demo đang có fallback khi xuanshu bridge/runtime không khả dụng: snapshot vẫn có dữ liệu quẻ để AI không luận giải trên dữ liệu rỗng, nhưng warning XUANSHU_REFERENCE_RUNTIME_FALLBACK cần được xem là tín hiệu kỹ thuật để harden runtime trước khi coi đây là production thương mại.
  • Nguồn trạng thái nên đọc trước: README.md, docs/README.md, docs/TEST_MATRIX.md, docs/product/api-contract.md và docs/deploy/vercel-demo-release-checklist.md.
  • .gitignore không được ignore root AGENTS.md; đây là artifact dự án cần theo dõi bằng Git. Các folder agent cục bộ như .agents, .claude và .gemini vẫn phải bị ignore.
  • Khi debug E2E local, kiểm tra network tab/trace trước: request tới https://api.tuvi.monet.uno từ localhost:4173 là sai ngữ cảnh test; request đúng phải tới http://localhost:3000.
  • Khi thêm quota mới, ném DailyQuotaExceededError hoặc RateLimitWindowError thay vì raw Error. Raw message quota cũ vẫn được hỗ trợ, nhưng typed error mới là contract bảo trì đúng.
  • Owner-scoping là invariant bắt buộc: các query đọc chart, divination context, explanation, history, conversation, annual report và vision result phải lọc theo owner_user_id. Sai owner nên trả về not found để tránh leak sự tồn tại của record.
  • Test supabase-persistence.gateway.ownership.test.ts khóa các query gateway quan trọng phải có điều kiện owner_user_id; cập nhật test này khi thêm bảng hoặc luồng đọc dữ liệu user mới.
