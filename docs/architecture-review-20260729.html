Deepening Opportunities

Codebase Architecture Review - ZiWei AI Platform

1. The God Class: SupabasePersistenceGateway

Strong

Files: apps/api/src/database/supabase-persistence.gateway.ts (955 lines)

Problem: The database gateway has become a shallow module. It acts as a dumping ground for every single database operation across all domains (Charts, Vision, Tarot, History). Because every service imports this massive interface, we have lost locality. When testing, developers are forced to mock irrelevant methods, leading to brittle test setups and high cognitive friction.

Solution: Deepen the database layer by applying the Repository Pattern. We will introduce a clean seam by splitting the gateway into domain-specific adapters (e.g., ChartsRepository, VisionRepository, HistoryRepository). The common Supabase client connection remains, but the exposed interfaces are heavily segregated.

Benefits: Feature modules only import the exact subset of DB operations they need (high leverage, high locality). Tests become trivial to mock because the interface is precisely sized to the feature.

2. Hardcoded Rules: QuotasService

Worth Exploring

Files: apps/api/src/modules/quotas/quotas.service.ts

Problem: The Quotas service currently hardcodes the quota definitions and check logic for every distinct feature. While functional, it is becoming a bottleneck. Adding a new AI feature requires digging into this core service to add new limits, violating the Open-Closed Principle and reducing locality.

Solution: Refactor into a Strategy pattern or a Rules Engine. Define an IQuotaStrategy interface that individual modules can register. The QuotasService becomes a deep module that evaluates rules dynamically based on the requested action.

Benefits: New features can define their own quota rules in their own directory (improving locality). The core Quota engine gains leverage by being ignorant of specific feature names.

Top Recommendation

Tackling Candidate 1 (SupabasePersistenceGateway) is the highest impact move right now. The gateway currently stands at nearly 1,000 lines. Refactoring it into Domain Repositories will instantly reduce cognitive load for developers and drastically clean up our unit testing mocks across the entire backend.
