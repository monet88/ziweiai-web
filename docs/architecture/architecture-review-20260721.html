🔭 Báo cáo Nâng cấp Kiến trúc Codebase

Các cơ hội "Deepening" (làm sâu module) dựa trên nguyên tắc ask-matt. Tập trung vào tính module (locality) và đòn bẩy (leverage) để giảm thiểu nợ kỹ thuật.

1. Tách God Module `api-client`

File: apps/web/src/lib/api-client/index.ts (hoặc các file call API chung)

Strong

Vấn đề (Friction):

Giao diện (Interface) của API Client đang quá "shallow" và ôm đồm. Mọi tính năng từ user, payment, đến tử vi đều gọi chung qua các hàm fetch chung chung. Không có tính Locality, rất khó để track lỗi riêng cho từng domain.

Giải pháp (Solution):

Deepen the module: Chuyển đổi thành các class/object Domain-specific Client (VD: ChartsClient, WalletClient, VisionClient). Ẩn hoàn toàn chi tiết truyền token, fetch payload đằng sau (seam) của từng client.

Trước (Shallow)

graph TD UI[Web Components] --> |"fetchJson('/api/charts', body)"| API[api-client/fetch-json.ts] UI --> |"fetchJson('/api/rewards', body)"| API API --> Backend[NestJS Backend]

Sau (Deep / Locality)

graph TD UI1[Chart UI] --> |"ChartsClient.create(dto)"| CC[ChartsClient] UI2[Wallet UI] --> |"WalletClient.checkin()"| WC[WalletClient] CC --> API[Base HttpClient] WC --> API API --> Backend[NestJS Backend]

2. Loại bỏ Domain Leak trong `ChartsService`

File: apps/api/src/modules/charts/charts.service.ts

Worth exploring

Vấn đề (Friction):

Service sinh lá số đang phải tự kiểm tra số dư XU và trừ tiền người dùng (Domain leak). Nếu chúng ta thêm Tarot hay Xem tướng, logic trừ tiền sẽ bị lặp lại ở mọi nơi, gây rủi ro bảo mật (quên trừ tiền hoặc trừ trùng lặp).

Giải pháp (Solution):

Sử dụng NestJS Interceptor hoặc một BillingService tập trung đứng trước (Decorator @RequireXU(10)). Interface của ChartsService chỉ tập trung đúng chuyên môn: Sinh lá số.

Trước (Leak)

sequenceDiagram Controller->>ChartsService: createChart() ChartsService->>Database: check XU ChartsService->>Database: minus XU ChartsService->>AstroEngine: compute() ChartsService->>Controller: return result

Sau (Deep / Adapter)

sequenceDiagram Controller->>BillingInterceptor: intercept() BillingInterceptor->>Database: handle XU safely BillingInterceptor->>ChartsService: next() ChartsService->>AstroEngine: compute() ChartsService->>Controller: return result

3. Gom nhóm Zod Validation Pipe

File: Toàn bộ Controller của API

Speculative

Vấn đề (Friction):

Các Controller hiện tại đang phải gọi hàm schema.parse() thủ công. Code lặp lại nhiều lần ở mọi endpoint (Shallow repetition).

Giải pháp (Solution):

Tạo một ZodValidationPipe làm Global Pipe hoặc Route Pipe của NestJS. Controller chỉ nhận vào DTO đã được định dạng và báo lỗi 400 tự động nếu sai format.

🏆 Đề xuất ưu tiên (Top Recommendation)

Nên ưu tiên giải quyết số 2. Loại bỏ Domain Leak trong `ChartsService` trước khi chúng ta code tính năng Tarot/Xem tướng. Bằng cách viết một Decorator/Interceptor tính phí chung, chúng ta có thể thoải mái thêm 10 tính năng mới vào sau này mà không bao giờ sợ bị lỗi trừ tiền hụt, đòn bẩy (leverage) tạo ra là cực kỳ cao.
